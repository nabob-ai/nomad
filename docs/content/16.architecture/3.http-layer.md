# HTTP 层架构 (cmd/nomad)

> **设计原则**: 核心 SDK 与 HTTP 框架解耦

---

## 架构设计

### 核心原则

**分层架构**:

```
┌─────────────────────────────────────┐
│   cmd/nomad (CLI 工具)           │
│   - 使用 Gin 框架                    │
│   - HTTP Server 实现                 │
│   - 子命令实现                        │
└──────────────┬──────────────────────┘
               │ 依赖
┌──────────────▼──────────────────────┐
│   pkg/* (核心 SDK)                  │
│   - 零 HTTP 框架依赖                 │
│   - 纯 Go 标准库 + 必要第三方库      │
│   - 可被任何项目安全导入             │
└─────────────────────────────────────┘
```

**依赖隔离**:

- `cmd/*` → 可以依赖任何框架（Gin, Chi, Echo 等）
- `pkg/*` → 只能依赖标准库和核心第三方库（不包括 HTTP 框架）

## 使用方式

### 作为 CLI 工具使用

```bash
# 编译
go build -o nomad ./cmd/nomad

# 运行 HTTP Server（使用 Gin）
./nomad serve --addr :8080

# 运行其他子命令
./nomad mcp-serve
./nomad subagent --type=Plan
./nomad eval
```

### 自己实现 HTTP 层（用任何框架）

#### 使用 Gin

```go
package main

import (
    "github.com/gin-gonic/gin"
    "github.com/nabob-ai/nomad/pkg/agent"
)

func main() {
    r := gin.Default()

    // 使用 nomad 核心功能
    r.POST("/chat", func(c *gin.Context) {
        // 创建 Agent 并调用
        ag, _ := agent.Create(...)
        result, _ := ag.Chat(...)
        c.JSON(200, result)
    })

    r.Run(":8080")
}
```

#### 使用 Echo

```go
package main

import (
    "github.com/labstack/echo/v4"
    "github.com/nabob-ai/nomad/pkg/agent"
)

func main() {
    e := echo.New()

    e.POST("/chat", func(c echo.Context) error {
        ag, _ := agent.Create(...)
        result, _ := ag.Chat(...)
        return c.JSON(200, result)
    })

    e.Start(":8080")
}
```

#### 使用标准库

```go
package main

import (
    "net/http"
    "github.com/nabob-ai/nomad/pkg/agent"
)

func main() {
    http.HandleFunc("/chat", func(w http.ResponseWriter, r *http.Request) {
        ag, _ := agent.Create(...)
        result, _ := ag.Chat(...)
        json.NewEncoder(w).Encode(result)
    })

    http.ListenAndServe(":8080", nil)
}
```

## 约束和规则

### ✅ 允许

**在 cmd/nomad/ 中**:

- ✅ 使用 Gin
- ✅ 使用任何 HTTP 框架
- ✅ 使用任何 CLI 库

**在 pkg/ 中**:

- ✅ 使用标准库（`net/http` 用于类型定义）
- ✅ 使用核心第三方库（UUID, 日志等）
- ✅ 定义接口而不是实现 HTTP handler

### ❌ 禁止

**在 pkg/ 中**:

- ❌ 导入 `github.com/gin-gonic/gin`
- ❌ 导入 `github.com/labstack/echo`
- ❌ 导入 `github.com/go-chi/chi`
- ❌ 导入任何 HTTP 框架

## 最佳实践

### 1. 作为 SDK 作者

```go
// ✅ 好的做法（在 pkg/ 中）
package agent

// 定义接口
type Agent interface {
    Chat(ctx context.Context, input string) (*Result, error)
}

// 实现逻辑，不依赖 HTTP 框架
func Create(ctx context.Context, config *Config) (Agent, error) {
    // ...
}
```

```go
// ❌ 坏的做法（在 pkg/ 中）
package agent

import "github.com/gin-gonic/gin"  // ❌ 不要这样！

func HandleChat(c *gin.Context) {  // ❌ 不要这样！
    // ...
}
```

### 2. 作为 SDK 用户

```go
// ✅ 安全导入
import (
    "github.com/nabob-ai/nomad/pkg/agent"
    "github.com/nabob-ai/nomad/pkg/memory"
    // 不会引入 Gin！
)

// ✅ 自己选择框架
import "github.com/gin-gonic/gin"     // 你的项目可以用 Gin
// 或
import "github.com/labstack/echo/v4"  // 或者 Echo
// 或
import "net/http"                     // 或者标准库
```

## 对比

| 方面          | 旧架构             | 新架构           |
| ------------- | ------------------ | ---------------- |
| **HTTP 框架** | pkg 中使用 Gin     | 只在 cmd 中使用  |
| **SDK 导入**  | 会引入 Gin 依赖    | 不会引入 Gin     |
| **灵活性**    | 用户被强制使用 Gin | 用户可用任何框架 |
| **兼容性**    | 可能版本冲突       | 完全隔离         |
| **维护性**    | pkg 膨胀           | 清晰分层         |

## 总结

### 核心思想

**SDK 核心不应该依赖任何 HTTP 框架，让用户自由选择**

### 收益

1. ✅ 用户可以用任何 HTTP 框架
2. ✅ 避免依赖冲突
3. ✅ 更小的依赖树
4. ✅ 更好的模块化
5. ✅ 更容易维护

### 原则

- **核心在 pkg/**：纯粹的业务逻辑
- **HTTP 在 cmd/**：具体的实现细节
- **用户自由**：想用什么框架就用什么
